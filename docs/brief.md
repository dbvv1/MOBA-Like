# MOBA-Like 设计任务书

设计变化直接改本文件；进度和阻塞写在 a1dbv TASKS。

## 目标

一局约 10 分钟的单线 MOBA：玩家操控一名英雄，和机器人一起推掉对方基地。品质重点有三项：技能出手和命中的手感、团战中看得懂谁在做什么、机器人的决策像人。

## 第一个可玩版本

- **地图**：一条兵线，双方各一座基地、两座塔、一个兵营。野区以后再加。
- **英雄**：先做 1 名，双方用同一英雄镜像对局；模拟层按 3v3 设计，实体数量和 AI 不写死。每名英雄 3 个技能加 1 个大招。第 1 名英雄至少包含指向技能、位移、持续效果和控制；方向弹道、范围和护盾随第 2 名英雄补齐。
- **对局**：小兵波次、塔的仇恨规则、金币与经验、等级成长、少量装备、胜负结算。
- **操作**：俯视角 3D；右键移动，QWER 施放，A 加左键攻击移动；镜头可锁定或拖边移动。

## 技术默认

- **TypeScript + Vite，Three.js 渲染**，与 Star-Rush 共用渲染经验。
- **模拟**：30 Hz 固定逻辑帧，渲染插值。只接受输入命令，按“种子 + 命令序列”可复现；对局结束输出状态哈希。Riot 为 League 服务器做确定性，最初是为了用录制的输入做快速、可重复的测试，后来又用于赛事中把对局恢复到之前的时间点（Chronobreak）。
- **寻路**：[recast-navigation-js](https://github.com/isaac-mason/recast-navigation-js)，即 Recast/Detour 的 WebAssembly 版本，Unreal 的导航网格用同一套算法；原定小兵用 Detour Crowd；当前 v10 先在现有位移之后加入有界兵间接触分离，保单一位移流程而不接第二套 Crowd 生命周期，适用边界见下文。
- **英雄 AI**：效用打分选意图（补兵、换血、撤退、推塔、支援），再由状态机执行；难度靠反应延迟、技能命中误差和决策噪声区分，不靠数值作弊。
- **素材**：优先许可清楚的 CC0 低多边形角色与动作包，再用 a1dbv 制作链补缺和统一风格。
- 换掉任何一项，在本节写一句理由。

### 可显式选择的 v9 单位阶段

`--content-version 9` 在单位阶段入口统一读取资格、目标与射程，先收集意图并提交全部移动，再结算已经承诺的普攻，最后统一标记死亡并发放奖励。移入射程要等下一单位阶段，移出射程不取消本阶段已经承诺的攻击；双方致命攻击可以互杀。护盾先吸收伤害，同一目标的敌方攻击者按稳定实体 ID 处理，以有效伤害首次跨过零血量的攻击获得原有击杀奖励，而不是改成最大贡献分配；后续已承诺挥击仍消耗攻击间隔，但不计尸体伤害。经验范围采用共同移动后的位置，已在本阶段死亡的旁观英雄不获得小兵范围经验；阵亡击杀者可得已承诺击杀的经验，但升级不会让死者恢复正生命值。

这只改变单位阶段，不把技能、弹道与塔的其他阶段宣称为全局同时结算或完全公平；旧 v1/v2/v7/v8 回放保留原行为。CLI 与网页新对局默认 v10，v9 仍供显式比较。原无英雄波线曾仅因遍历次序自行形成优势；v9 的同一对称波线保持位置与血量对称，直到时限也不自行决出胜负，需要英雄参与推进。

## 表现事件接口

模拟的 `snapshot().events` 只包含最近一次实际逻辑步产生的只读事件副本，不属于 `SimState`、状态哈希或输入回放格式；相同版本、种子和逐 tick 有序输入会重新产生相同事件。初始为空，下一次有效 `step` 替换整批，终局后拒绝输入不清除最后一批。每批按真实产生顺序编号 `tick + ordinal`；重读快照不会消费事件，修改返回副本不影响模拟。

呈现必须在**每次** `step` 后取批，按 `tick + ordinal` 去重并放入自己的待呈现队列，再按渲染帧播放；一帧推进多个逻辑步也逐步收取。只读取最终渲染帧的快照会漏掉中间批，接口不承诺历史补发；重开对局清空消费游标和队列。模拟只保留一个逻辑步的批，不做无界累计或网络事件总线。

- `castStarted`：通过实际校验、已支付资源的施法，携带 `castId/heroId/abilityId/slot`。零前摇技能也有开始事件。
- `castResolved`：该施法真正提交其 delivery（弹道、区域、位移或直接效果），**不等于命中**；开始和提交可在同 tick。实际失能、死亡、目标失效或导航失败产生 `castCancelled` 与具体原因，不由 `castSlot` 消失推测；已有 stop/move 不取消施法的规则不变。
- `minionDied`：只在实际 cleanup 移除死亡小兵时发出，带 `entityId/team/position` 副本。兵已立即退出模拟、碰撞、目标与奖励流程；表现只能给已存在的兵实例播放约 1.03 秒原 death 片段及 0.15 秒尾停，不从缺实体推断死亡、不为初始死兵生成尸体。尾段不再提供选取 ID／血条，按可见渲染时间推进（后台无 draw 因而暂停，终局可收完），重开立即释放；不改变旧版本状态哈希或回放。同批出手反馈可用此死亡位置／阵营补齐已被 cleanup 移除的小兵端点（包含 v9 互杀），不从一般缺实体猜测；出手轨迹仍不等于命中确认。
- `basicAttack`：已通过资格、将消耗攻击冷却的普攻，带 `sourceId/targetId`，涵盖英雄、小兵和塔。v9 在稳定排序的已承诺攻击提交处发出，因此同阶段已被前一击致死的目标仍可有后续空挥，但没有尸体伤害事件；未取得资格的目标失效不发攻击事件。护盾全吸收也不抹掉出手。
- `heroDamaged`：真实伤害路径对英雄结算，带 `sourceId/targetId/abilityId|null`、扣除护盾后实际损失的 `hpDamage`（不计过量击杀伤害）及 `shieldAbsorbed`。全护盾吸收时 HP 损失为零；它不是命中、治疗、成长或死亡的通用推断。旧顺序结算和显式 v9 的阶段伤害均在各自真实结算处记录，不改变伤害、奖励、随机数或阶段顺序。

## 玩家英雄选择（二次修改）

网页的 Next match hero 从现有 catalog 的稳定英雄 ID／名称／技能引用生成选项；选择在下一次 Restart 创建新 `Simulation` 时生效，不热换当前实例。默认 Veyra；可选已有 Morrow，对手仍为既有普通难度 Veyra。重开保留选择，但重建模拟、输入队列、HUD 与表现生命周期；加载期间禁用选择，失败后可保留／更改选择重试。

此修改只接网页初始化、选择控件、玩家说明和客户端检查；复用现有按 definitionId／targetType 工作的 controls、HUD、瞄准与技能执行，不新增数值、资源或模拟版本。Morrow 的 W 为自身护盾，不需要地面点击；Q 为方向弹道，E/R 为地面技能。原 Veyra Q 已有的 v1 指向／v2+ 方向弹道版本契约与旧回放解释不变，选择新局不修改历史回放。角色源沿已有 team 表现复用，不宣称为两名英雄另制独立美术。

## 当前质量单元：一次基本战斗

功能与质量分别验收。双英雄、输入与软件 WebGL smoke 已采用，**不代表整体品质完成**。当前只做英雄随一波小兵进入塔前、施放／命中／受击、读懂塔威胁并撤回的一段战斗；场地、建筑、小兵、英雄、技能、声音和界面一起提升，不继续扩英雄数量或事件框架。

主比较按用户最新方向尽可能参照 [《英雄联盟》官方基础玩法与战斗展示](https://www.leagueoflegends.com/en-us/how-to-play/)中的一次线前／塔前交战：走 A 与停止的响应、施法前后动作承诺、弹道与真实命中的区分、敌我和塔威胁、声音主次、HUD 信息层级。目标是用 a1dbv 已有技能、输入、动画、渲染、资源与测试模块串起完整客户端体验，不以新玩法创意替代成熟体验；不复制 Riot 的素材、技能名、品牌或商业内容，也不扩整套英雄池／在线体系。

[Thronefall 官方小规模战斗画面](https://store.steampowered.com/app/2239150/Thronefall/)保留为低多边形地景／建筑轮廓、明暗层级的辅助参照，不再作为基本 MOBA 战斗品质的终点。参考只在本地并排留截图／录像，公开记来源与差距。现有合法统一资产继续采用日照石径、青绿守望与赭红入侵，技能高亮不能淹没角色；若与 LoL 基础战斗的反馈／控制清晰度有差距，要在本段战斗中实改复评，而不是靠换风格宣称达标。

资源先比较许可清楚的成熟现成包。当前首选 [KayKit Medieval Hexagon 免费版](https://kaylousberg.itch.io/kaykit-medieval-hexagon)的场景与建筑，与 Kenney Fantasy Town 场景比较后，以统一风格决定实际采用。[Adventurers 免费角色](https://kaylousberg.itch.io/kaykit-adventurers)在官方页面标明 CC0，但既有取回动作受阻，不换镜像绕过；角色先沿已有自有骨架／动作源实质重塑可读骑士轮廓，必须同屏比较，不能因自制而降低质量目标。只取免费内容；不把付费兵种或 Blender 源文件当免费。取得并验证后记来源与具体选用项，不能用程序生成几个新几何体冒充质量提升。

每轮先实际操作，非作者再按相同战斗阶段与参照并排评估：①单位／塔／通路一眼可辨；②施放、命中、护盾吸收与受击能分清；③目标、冷却、生命与危险不用读整段文字；④声音有主次且不刺耳／堆叠；⑤输入、相机、重开形成完整体验。列出最大的差距，优化后重评，达到参照所选维度的水平才完成本单元。自动检查／旧 smoke 只证明功能底线，不能代替质量结论。原云 Chrome 标签页缺 WebGL2；现在 own-cloud 正常 Terminal 的独立 sandbox Chromium 已实证软件 WebGL 可用，本轮用同一安全入口取得真实正常输入画面，并区分软件渲染、主观听感与硬件手感。旧通过记录和新增截图均不自动代表品质 PASS。

塔前表现采用近距离出现的分段边界，按敌塔真实攻击距离加玩家半径绘制；这只是玩家中心的可受攻击范围，不表示当前仇恨，也不保证边界外没有其他威胁。只有指向玩家的真实塔普攻事件触发短促边界闪色，塔出手轨迹与技能区域分开；不预测尚未发生的伤害。低矮塔基只提供建筑接地与定位，不新增碰撞或改变导航；地表保留原不齐边缘，不采用造成光晕感的软肩试稿。

## 合入门槛

能玩、`npm test`、构建和 `npm run smoke` 通过、没有新增异常，就合入 `main`；可玩的集成版不留在候选分支，没达标的指标写进“当前差距”在 `main` 上继续改。

模拟层的合入门槛只有两条：`npm run sim -- --games 200 --seed 1` 0 异常、0 卡死（有移动目标、未受控也未施法的单位静止不超过 10 秒），同一种子和命令序列重放两次状态哈希一致。镜像胜率、高低难度胜率（目标 80%）、对局时长（目标 8–12 分钟）和技能施放／命中／伤害占比是调参报告：每次改数值前后跑一遍对照，结果写进“当前差距”，不阻塞合入。

## 当前差距

- 2026-10-26，旧 v8 校准记录：正常 200 局（seed 1 起）有 1 局超时（seed 136），时长中位数 709.43 秒；高低难度 182/200（91%），中位数 543.77 秒；镜像 500 局（seed 201 起）蓝方 278/500，95% 区间 [51.22%, 59.90%] 未覆盖 50%，中位数 709.53 秒。三批无新增异常或卡死；这些未达标项继续校准，不宣称已解决。

## 里程碑

1. **可玩**（当前）：浏览器打开即可操控 1 名英雄对 1 名机器人英雄打完一局，小兵、塔、基地、成长和胜负完整，基础功能已采用；占位不再作为当前质量单元的完成标准，手感、画面、声音按上述参照循环继续提升。顺序：先做模拟层和无画面 `sim`，再接占位几何渲染和操作，最后换正式素材。
2. **第二次需求修改**：加第 2 名英雄，并把一个已有技能从指向改为方向弹道。按 [05 §11](https://github.com/dbvv1/a1dbv/blob/main/domains/game-dev/05-gameplay-architecture.md#11-给-ai-第二次修改的最小契约) 记下改了哪些文件、哪些资源要重做、回放和数据是否仍兼容。
3. **扩展**：3v3、第 3 名英雄、野区，在第 2 步完成后再定。

## 不做

联网对战、匹配排位、商城、皮肤、反作弊。以后要联网，在确定性模拟上做帧同步，另开里程碑；届时再处理浏览器之间浮点数学结果不一致的问题。

### v10：兵群接触空间

v10 以 v8 为基础，仅增加活兵之间的有界接触分离，不同时采用 v9 的单位两阶段伤害规则。双方沿相同规则：单位阶段的移动／普攻承诺完成后，读取同一组位置，按固定 ID 累加成对推离，再统一提交；死亡不参与，眩晕兵作为不能被推移的障碍，英雄不被兵群推移。完全重合无几何法线时，用稳定 ID 决定相反横向，不能由此宣称所有旋转对称。每步最多修正 2 米／秒 × 固定步长；只接受现有 NavMesh 上可由该短距离直达的局部落点，短折线路径也拒绝直接跨弦，失败仍保重叠，不接受超预算的远点跳转。当前只验证了已发布的凸矩形通路；现有路径包装会滤去 5 厘米内的近点，因此这些检查不是任意复杂凹角／薄障碍的连续碰撞保证，关卡增加此类障碍前须补保真直达查询。

已承诺的普攻不会因为随后分离而撤回；分离求解本身不依赖输入数组顺序，但 v10 仍保 v8 的顺序单位更新，不能宣称整 tick 反序不变。塔阶段及下一 tick 射程读取新实际位置。这会改变阵型、接敌与伤亡，不是纯渲染优化，不借旧回放哈希宣称新玩法不变。旧 1／2／7／8／9 的规则保留，CLI／网页新对局采用 10；旧回放按记录版本读取，显式 8 仍可运行。它是软接触修正，不是完整 Crowd／刚体系统，也不保证任意密度或窄口零重叠。品质判断仍需正常基本战斗及非作者实图，不以数值重叠降低代填。

### 玩家指定普攻目标

右键真实画面中可拾取的存活敌方单位，会提交已有 `attack` 命令，追入现有射程后按版本规则普攻；不是点击即命中或自动改选最近敌人。右键地面或友方仍移动，右键会取消当前技能瞄准。点到已失效或不可攻击敌方不会偷偷转成向其脚下移动；UI 面板不透传到世界。当前玩法没有战争迷雾，本入口不增加画面之外的目标信息，尸体仍不参与拾取。模拟阶段、伤害与回放版本不变，网页／CLI 继续 10。

操作参照：Riot Games [Champion Insights: Zeri](https://www.leagueoflegends.com/en-gb/news/game-updates/champion-insights-zeri/) 的普攻右键与技能射击区分；本例复用自己的目标命令与可见拾取，不照搬英雄机制。

## 键位设置与菜单交接

在现有 Controls & help 内打开 Keyboard settings，按稳定技能槽和攻击移动／停止／锁镜头动作编辑一份键位草稿。它复用 `KeyboardBindings → createControls → SimCommand`，不改变模拟、技能资格或回放。HUD、帮助与英雄技能提示读取同一有效绑定；右键点地移动／点敌攻击不变。首版沿逻辑 `KeyboardEvent.key`，允许 A–Z、0–9、方向键与 Space；Esc、Tab、Enter 保留导航，不支持组合键、IME、非拉丁键或手柄改键。

进入原生模态面板先禁用玩法输入、清空尚未交给模拟的命令和旧瞄准，局部对局暂停。背景场景／HUD／商店不能收操作，焦点留在面板；关闭回菜单入口，点击战场继续。Tab、切行、失焦取消捕获但保留草稿；捕获中 Esc 只结束捕获，之后 Esc／Cancel 取消并关闭。冲突显示占用动作，只有明确 Swap 才交换两键。保存成功才应用与更新提示；存储失败保持有效键位与草稿，留在面板重试／取消。恢复默认也先改草稿，保存时删除本项存储覆盖，不能仅因草稿与有效值相同而禁用保存。

重开销毁旧编辑器、监听和输入所有者，丢弃未保存草稿，沿用已保存键位与英雄选择；对局时钟不补算菜单停留时间。上述 DOM／客户端测试是 CPU 功能证据；原生模态焦点、背景 inert、布局、真实键鼠与手感仍需正常浏览器验收，不能用 DOM 模拟替代。
