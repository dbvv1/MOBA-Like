# 本机单人对局续玩

刷新页面后选择 **Continue saved match** 继续，或 **New match · replace save** 开新局。**Play without saving · keep old save** 不动旧档。只有本浏览器同源存储，没有账号、上传或跨设备同步。

`src/save/match.ts` 沿用原 `Simulation`／`HeroBot`：记录种子、双方英雄、内容版本、机器人种子／难度及玩家输入帧。在新实例中逐帧运行原机器人并消费玩家输入，重建私有 RNG／感知记忆，终点核完整模拟哈希；恢复期间不接实时输入、渲染或声音。`src/save/storage.ts` 只负责一个原子替换的 Web Storage 键，不把 UI snapshot 当存档。

规则／AI／导航／依赖由 `tools/save-compatibility.ts` 构建期生成指纹。不同指纹、未知格式、坏数据或复演哈希不符都保留旧字节，不自动升级、不改规则迎合旧档。更新了规则后需要开新局；目前不承诺跨浏览器／平台确定性。DOM、音频、设置、网络身份和凭据不进入存档。

每 10 秒模拟时间及隐藏页面时保存已提交帧，**Save match** 可手动保存／重试。浏览器突然退出可能失去最后一次成功保存后的输入；Web Storage 返回成功不等于断电耐久。`navigator.locks` 保证同源只有一页持有保存权；另一页或不支持该 API 的浏览器仍能游玩，但不写存档。读取、配额或删除失败显示明确状态，不删除旧档腾空间。

## 开发接缝

1. 创建一个 `LocalMatch(recipe, navigation, compatibilityId)`，旧客户端每 tick 的 `sim.step([...issued,...bot.think(sim)])` 替换为 `match.step(issued)`，不要让两处各推进一次。
2. 恢复时先 `decodeMatchSave`，再 `restoreMatch`；后者返回的是已重建 bot 的同一会话所有者，而不是只恢复 Simulation。
3. 只有完整恢复成功后才能创建表现／输入层。初次恢复快照的历史 `events` 不送进表现层；下一真实 tick 继续读新事件。
4. `checkpoint()` 只含已消费的玩家命令，不含未消费按键队列。失焦清队列，暂停期间不增加逻辑帧；新局重建所有者，终局清除该存档。

本模块针对现有 1v1 单机、最长 20 分钟和不超过 24,000 个玩家命令；超过预算停止保存但仍可继续玩。不提供多人、即时任意状态快照、云同步或通用迁移框架。

## 增加字段仍能读旧档

格式 2 新增 `view.cameraLocked`：续玩先对准恢复后的英雄，再保留玩家的镜头锁定选择；自由镜头的原位置不保存。格式 1 的已知语义是重建后锁定，因此只对该格式补 `true`；格式 2 明确保存的 `false` 不被默认值覆盖，缺字段则拒绝。`tests/save/fixtures/v1-match.json` 来自格式 1 实际模拟的 180 帧检查点，升级后由原模拟复演核同一哈希；迁移只在内存进行，不改旧字节。玩法规则指纹与存档格式版本分开：增加这个视图字段不借机迁移不同规则的对局。
