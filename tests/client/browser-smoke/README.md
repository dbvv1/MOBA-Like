# Browser smoke

From the repository root, `npm run smoke` builds the web client and runs the existing input, restart, hero selection, keyboard remapping and save/resume sequence on the current default `/`. Run `MOBA_SMOKE_VARIANT=quiet npm run smoke` to run that same sequence on the existing `/candidate.html?materials=quiet-family-v1&lighting=forest-light-v1` trial. Omitted variant means `default`; empty or unknown variants fail before starting the server or browser. Both use v11 + forest lighting with quiet materials; the previous visual default remains accessible at `/?materials=baseline`. Neither enables the separate v12 command-buffer or Camera + Q/W trial.

Both HTML entries load `src/client.ts`. The homepage supplies forest lighting through `data-default-lighting`; the quiet trial supplies the same value explicitly. With no `commands`, `camera` or `audio` parameters, both use the same v11 simulation, baseline camera and audio; only the quiet material option changes. This tests the existing opt-in candidate against today's default, not a future promoted homepage build. Re-run the actual promoted entry if its defaults or build change.

The sequence requires a live Three/WebGL2 canvas, advancing simulation, keyboard/mouse E with its real snapshot zone and matching Three effect objects, pointer movement and stop commands, camera controls, HUD layout, varied pixels and no browser errors. It rejects renderer/material fallback, including immediately after each restart and save/resume, and checks that the selected URL is unchanged. The ordinary client now exposes `materials.configured/active` from the actual world-owned texture family and successful live frame submission (the same source as capture diagnostics), not by echoing the URL. Missing resources, fallback, no submitted frame and lost WebGL context cannot satisfy the material assertion. This establishes installed family plus submitted frame, not pixel quality or a GPU shader profiler result. Each run records the selected route in `report.json` and `manifest.json`; compare runs from the same clean commit/build and renderer. Quiet rendering quality still needs actual same-view screenshots and independent comparison.

Legacy v10 remains a separate load/progression check. Retired `lighting=stylized-diffuse` must produce a visible retirement notice and restore forest WebGL rendering, rather than activate a removed mode. The final default-entry check remains separate. These extra checks do not run the full input sequence. The original baseline-lighting candidate is no longer the primary sequence; use its existing route/unit coverage for that historical lighting choice. This runner does not validate the v12 command-buffer or full Camera + Q/W trial.

The short `npm run smoke` remains the input/regression sequence, not complete-match acceptance. Use `npm run smoke:match` for the default, or `MOBA_SMOKE_VARIANT=quiet npm run smoke:match` for quiet. This adds a fresh, naturally progressing match **before** the existing sequence. No simulation mutation, debug end hook, virtual clock, shortened rules limit, automatic player commands or checkpoint resume is used. It watches from tick zero through a real base-destruction or native rules-timeout outcome; an infrastructure timeout fails and never creates a winner. The normal opposing bot plays against an idle Veyra player using the shipped seed/rules. CPU reproduction currently ends by blue-base destruction at tick 9010 (300.33 simulated seconds); browser wall time may be longer. This is a deterministic passive match, not representative player/teamfight stress coverage or quality acceptance.

Full-match mode samples every observed RAF callback from first logic update through terminal render, retaining unclamped slow frames in `full-match-frames.json`, including raw RAF timestamps, adjacency validation and partial samples on wait failure. After the terminal screenshot it uses the ordinary Restart button, verifies a fresh running tick, further progression and actual right-click movement in that same new match, then continues the original sequence. `report.json` adds natural end reason/winner, start/end timestamps, full-match viewport/DPR/canvas/renderer, callback CPU and frame-interval mean/p50/p95/p99/max and over-33.333ms counts. CPU callback duration excludes observer snapshots, but frame intervals include observer overhead. These are not GPU execution timings or just average FPS; simulation delta clamping never clamps recorded intervals. Hidden pages (including visibility events), open pause dialogs, restarted/non-fresh matches, missing terminal state and malformed timings fail. The one-hour harness limit and one-million-frame ceiling fail rather than truncate successful evidence. A native 20-minute rules timeout is recorded distinctly, not called a base victory.

Compare both variants from the same clean commit, renderer, dimensions and scenario. No automatic “not slower” threshold or promotion decision is inferred. `report.passed` means only the requested functional checks passed; `fullMatch.acceptanceReady` remains false, so this output cannot be used as a completed promotion gate. Full-match start/end material states are recorded separately and checked; comparative performance and blind quality review are still required. Browser full-match execution, performance comparison, active-combat frame costs and quiet-vs-current-default blind comparison remain unverified until actually run; CPU tests only validate the observer/summary contract and the shipped idle recipe's natural ending. Animation quality, sound and balance still need separate review.

Install Chromium through `npx playwright install chromium` in an authorized environment, or set `MOBA_SMOKE_CHROMIUM` to an existing absolute executable path. The default keeps the Chromium sandbox enabled. `MOBA_SMOKE_RENDERER=software` explicitly selects software WebGL; omitted renderer uses GPU defaults. Sandbox overrides are rejected; the harness never retries with different safety settings. Do not work around an access denial.

`npm run smoke:serve` builds and serves the same files without launching a browser. It prints its actual loopback URL; Ctrl+C closes the listener.

Screenshots and JSON are local ignored files in a unique `smoke-artifacts/` directory, or a new directory selected by `MOBA_SMOKE_OUTPUT`. Existing evidence is never overwritten. Failures distinguish launch, HTTP load, initialization, WebGL, input/simulation, pixels and browser errors; cleanup failures also fail the run. `npm test -- tests/client/browser-smoke/harness.test.ts` tests variant selection against production parsers, state/fallback rejection, helper failures and HTTP listener cleanup without launching a browser. These CPU checks do not establish a browser pass.
