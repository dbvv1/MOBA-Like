# Browser smoke

From the repository root, `npm run smoke` builds the web client and runs the existing input, restart, hero selection, keyboard remapping and save/resume sequence on the current default `/`. Run `MOBA_SMOKE_VARIANT=quiet npm run smoke` to run that same sequence on the existing `/candidate.html?materials=quiet-family-v1&lighting=forest-light-v1` trial. Omitted variant means `default`; empty or unknown variants fail before starting the server or browser. Both use v11 + forest lighting; neither enables the separate v12 command-buffer or Camera + Q/W trial.

Both HTML entries load `src/client.ts`. The homepage supplies forest lighting through `data-default-lighting`; the quiet trial supplies the same value explicitly. With no `commands`, `camera` or `audio` parameters, both use the same v11 simulation, baseline camera and audio; only the quiet material option changes. This tests the existing opt-in candidate against today's default, not a future promoted homepage build. Re-run the actual promoted entry if its defaults or build change.

The sequence requires a live Three/WebGL2 canvas, advancing simulation, keyboard/mouse E with its real snapshot zone and matching Three effect objects, pointer movement and stop commands, camera controls, HUD layout, varied pixels and no browser errors. It rejects renderer/material fallback, including immediately after each restart and save/resume, and checks that the selected URL is unchanged. The ordinary client does not expose the capture-only `materials.active` field: route/parser and fallback checks are not a direct shader/material-active observation. Each run records the selected route in `report.json` and `manifest.json`; compare runs from the same clean commit/build and renderer. Quiet rendering quality still needs actual same-view screenshots and independent comparison.

Legacy v10 remains a separate load/progression check. Retired `lighting=stylized-diffuse` must produce a visible retirement notice and restore forest WebGL rendering, rather than activate a removed mode. The final default-entry check remains separate. These extra checks do not run the full input sequence. The original baseline-lighting candidate is no longer the primary sequence; use its existing route/unit coverage for that historical lighting choice. This runner does not validate the v12 command-buffer or full Camera + Q/W trial.

This is the full existing smoke sequence, not a natural complete-match test. It does not measure frame-time distributions or compare performance, grade animation quality, sound or game balance, or establish default-promotion acceptance. Complete-match smoke, frame costs and quiet-vs-current-default blind comparison remain required before promotion.

Install Chromium through `npx playwright install chromium` in an authorized environment, or set `MOBA_SMOKE_CHROMIUM` to an existing absolute executable path. The default keeps the Chromium sandbox enabled. `MOBA_SMOKE_RENDERER=software` explicitly selects software WebGL; omitted renderer uses GPU defaults. Sandbox overrides are rejected; the harness never retries with different safety settings. Do not work around an access denial.

`npm run smoke:serve` builds and serves the same files without launching a browser. It prints its actual loopback URL; Ctrl+C closes the listener.

Screenshots and JSON are local ignored files in a unique `smoke-artifacts/` directory, or a new directory selected by `MOBA_SMOKE_OUTPUT`. Existing evidence is never overwritten. Failures distinguish launch, HTTP load, initialization, WebGL, input/simulation, pixels and browser errors; cleanup failures also fail the run. `npm test -- tests/client/browser-smoke/harness.test.ts` tests variant selection against production parsers, state/fallback rejection, helper failures and HTTP listener cleanup without launching a browser. These CPU checks do not establish a browser pass.
